# Agent report: Revisory676 + livvaa/AulaToolkit (condensed key facts)

- Revisory676 = one commit on an older gavindi snapshot; own additions only dongle code (tools/aula_l99_hacky protocol.py:1212-1317, device.py:183-316, cli.py:256-303), no captures/tests backing them.
- Q1 dongle: Clock set — dongle ACKs (gavindi 0.9.23), panel change not shown; AT marks Clock ✅ for L99 2.4 GHz but L99 support is beta/verified:false. Stats/weather — unknown, offsets from disassembly only; AT dongle clock sends 14 payload bytes (no stats). Music — no dongle path in either repo (design statement, not tested negative). Upload — cable only (screen is separate CDC device). Lighting/settings/keymap/macros — AT implements over dongle (tested on S75 Pro, not L99).
- "2.4 GHz telemetry" = keyboard→host battery/presence: query 20 01 00 … 00 21 (32 B, checksum last byte), reply 20 01 00 <pct>. gavindi's "SESSION_QUERY" expected reply 20 01 00 64 is just battery=100%. No reply = keyboard asleep/off.
- Dongle framing: interface 3 vendor collection, 32-byte OUTPUT/INPUT reports (not feature). Write report-ID 0 + 32 B. Frame: cmd len seq data[28] checksum (sum bytes 0..30 & 0xFF). Commands: LIGHT 05, SETTINGS 07, MACRO 09, TIME 0C, KEYMAP 10, KEYMAP_FN 12, USER_LIGHT 14, BATTERY 20, session-init 02. Short commands: first 14 cable-payload bytes at frame[3..16], AA 55 at 17..18.
- Dongle clock: 0C 10 00 | 00 01 5A YY MM DD hh mm ss 00 WD 00 00 00 | AA 55 | 0… | cksum (AT + gavindi, ACKed). Revisory moved trailer to 25..26 with monitor fields 16..24 (+3 shift) — plausible, untested, changes the ACKed clock packet.
- Bluetooth: no config interface; only OS battery level.
- Wired kbd 0C45:800A: 64-B feature reports, report ID 0, interface 3 (gavindi) — AT probes every collection for a working 64-B feature read and prefers usage page >= 0xFF00 (use that approach). Dongle 05AC:024F interface 3 (some dongles 0C45:FEFE — excluded for L99). Dongle product string "2.4G Dongle".
- Wired session: 04 18 → 04 <op> [8]=nblocks → blocks → 04 02 → 04 F0; reply byte3 01 ack / FF busy.
- Clock+stats op 0x28 all fields confirmed on hardware by gavindi; vendor streams ~1 Hz.
- Music op 0x78: commit → 04 78 [8]=1 → block RHY BGMODE 0x64 <23 levels 0..100> [26]=bg brightness, ~47 ms; 17 bands rendered; confirmed on hardware (gavindi).
- Lighting: op 0x13 effect; op 0x23 per-key persistent; op 0x20 live volatile; dongle effect 05 10 00 mode R G B …
- Q8 version: dongle session-init reply (02 00 … 00 02 → 02 00 00 40 30 00 00 45 0C 0A 80 29 01 FF FF …) byte 11 = 0x29 on L99 — likely the RECEIVER's version (unchanged across pairing). No wired/screen version query. Driver versions seen: 1.0.1.4 (gavindi), 1.0.0.7 (AT).
- Confirmed on hardware (gavindi): wired handshake, per-key RGB + readback, effects, clock w/ all stats fields, music, settings, photo/bg/GIF uploads; dongle session-init, battery reply, clock ACK. AT: dongle battery/lighting/settings on S75 Pro.
- Revisory bugs: dongle settings packets clobber other state; --handshake dispatch deleted; online check uses 0x02 (dongle answers even with kbd off).
- Safety: Rev — no flashing, no network; --force-address/--force-size can overwrite screen firmware; persistent 0x23/0x11; --send-hex; udev + curl|sh in CI; documentation/Firmware/.enigma2 PE32 fragment — don't run; system_monitor_block.md:100 contains vendor weather API URL with embedded token — don't call. AT — Windows Electron, auto-updates from GitHub, PowerShell, taskkill, renames vendor exes in Program Files via elevated helper, Task Scheduler autostart; factoryReset overwrites keymaps/macros/lighting; S75 Pro screen path (op 0x72, 4096-B output reports, probes by writing 0xFF to other collections) — never use on L99.
- Phase 2 bottom line: stats must be smoke-tested; music expect cable-only; uploads cable-only; battery/presence over dongle cheap and solid.
